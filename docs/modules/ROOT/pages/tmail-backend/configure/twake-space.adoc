= Twake Space
:navtitle: Twake Space

The Twake Space extension gives each TwakeSpace space a team mailbox, keeps its members in step with the space, and
reports its mail to the space feed. It replaces the Twake Mail side service.

== Configuration

The extension is loaded when `space.properties` contains `enabled=true`. Every other key is optional.

.space.properties
|===
| Key | Default | Description

| `enabled` | `false` | Loads the extension.
| `rabbitmq.uri` | the server of `rabbitmq.properties` | RabbitMQ server holding the exchanges below. One connection serves every component of the extension.
| `space.exchange` | `space` | Where the space events are read, and where `twake.space.sync.requested` is published.
| `dns.exchange` | `admin-panel` | Where the admin panel publishes its DNS validation event.
| `dns.routingKey` | `dns.validated` | Routing key of the DNS validation event.
| `activity.exchange` | `activity` | Where the `com.twake.mail.*` activity events are published. Declared as a durable topic exchange.
| `queue` | `tmail-space` | Queue of the space and DNS events. Quorum when `rabbitmq.properties` asks for quorum queues, with a single active consumer.
| `deadLetterQueue` | `tmail-space-dead-letter` | Where failed events go. Nothing replays them: request a sync instead.
| `teamMailbox.prefix` | empty | Put before each team mailbox name, like `space-` for `space-sales@acme.com`. Lowercase letters, digits or `_`, ending with a dash.
| `retention` | `30d` | How long the team mailbox of a deleted space is kept before being deleted.
| `purge.interval` | `1h` | How often team mailboxes past the retention are deleted.
| `teamMailboxEvents.enabled` | `false` | Publishes the team mailbox `received` and `sent` events described below.
| `teamMailboxEvents.exchange` | `tmail` | Topic exchange of these events.
| `teamMailboxEvents.receivedRoutingKey` | `team-mailbox.message.received` | Routing key of `received` events.
| `teamMailboxEvents.sentRoutingKey` | `team-mailbox.message.sent` | Routing key of `sent` events.
|===

Delivery is at least once. Every handler is idempotent, and published events carry deterministic ids, so a redelivery
changes nothing on TMail's side and consumers can deduplicate on the id.

== Storage

The extension adds no table. The space of a team mailbox is stored as annotations of its root mailbox:

- `/shared/vendor/twake/organizationId` and `/shared/vendor/twake/spaceId`, written when the mailbox is created.
- `/shared/vendor/twake/deletedAt`, written when the space is deleted.

These keys are read only: members can read them with IMAP `GETMETADATA`, nobody can change them with `SETMETADATA`.

== Consumed events

|===
| Exchange | Routing key | Effect

| `space` | `twake.space.created` | Creates the team mailbox of the space if it has none, then sets its members.
| `space` | `twake.space.synced` | Same, and makes the members those of the event, removing anyone else. Publishes `provisioned` again.
| `space` | `twake.space.member.added`, `twake.space.member.role.changed` | Adds the named members, or changes their role.
| `space` | `twake.space.member.removed` | Removes the named members.
| `space` | `twake.space.updated` | Nothing: a team mailbox keeps its address when its space is renamed.
| `space` | `twake.space.deleted` | Removes every member and writes `deletedAt`. The mailbox and its mail stay until the purge.
| `space` | `twake.space.sync.completed` | Closes, as on a deletion, the live spaces of the organization the snapshot does not list.
| `admin-panel` | `dns.validated` | When validated, publishes `twake.space.sync.requested` for the organization.
|===

Space events must carry `organizationDomain`: TMail finds a space's team mailbox among the domain's ones. An event for
a domain TMail does not have is skipped, the DNS validation of the organization brings its spaces back. A deleted
space stays deleted: later events about it are ignored.

Roles: `admin` becomes `manager`, `editor` becomes `member`, `viewer` gets no access. Members are matched by email,
case insensitive.

=== Addresses

The address of a team mailbox is the space name with accents dropped, lowercased, every run of characters other than
`a-z`, `0-9`, `-` and `_` replaced by one `-`, dashes trimmed, at most 64 characters (`space` when empty), under
`teamMailbox.prefix`. When another space, a user, an alias, a group or an LDAP mailing list holds it, `-2`, `-3`... up
to `-20` are tried. When the address is a team mailbox no space holds, the event fails: bind it with the route below
if it is the space's.

== Published events

On `activity`, as CloudEvents 1.0 with the event type as routing key and the event id as AMQP message id:

- `com.twake.mail.space.provisioned.v1`, id `<space id>:<root mailbox id>:provisioned`, once the team mailbox is created and on every sync.
- `com.twake.mail.message.received.v1` and `com.twake.mail.message.sent.v1`, id `<root mailbox id>:<message id>:<direction>`,
for the mail of team mailboxes bound to a live space.

On `space`: `twake.space.sync.requested`, body `{"organizationId", "id", "timestamp"}`, both ids optional.

== WebAdmin routes

- `POST /spaces?action=sync[&organizationId=...][&spaceId=...]`: publishes `twake.space.sync.requested`. `spaceId` needs `organizationId`. Answers `204`.
- `GET /domains/{domain}/team-mailboxes/{name}/space`: the space binding of a team mailbox, `404` when it has none.
- `PUT /domains/{domain}/team-mailboxes/{name}/space` with `{"organizationId": "...", "spaceId": "..."}`: binds an existing team mailbox to a space, then requests a sync of that space. Answers `204`, `404` for an unknown team mailbox, `409` when it is bound to another space.

== Team mailbox events

With `teamMailboxEvents.enabled=true`, an event is published each time a team mailbox receives or sends a message:

- A message delivered into any folder of a team mailbox produces a `received` event.
- A message added to the `Sent` folder of a team mailbox, whether appended, moved or copied, produces a `sent` event.
- Other additions, and messages in personal mailboxes, are ignored.

Events are persistent JSON messages whose AMQP message id is `<messageId>:<direction>`. When a publication fails, the
event bus retries the whole mailbox event, so events published before the failure are sent again.

Example of a `received` event:

[source,json]
----
{
  "teamMailbox": "marketing@linagora.com",
  "domain": "linagora.com",
  "direction": "received",
  "mailboxPath": "marketing.INBOX",
  "mailboxId": "6e3c9a40-c1ab-11f1-bdf6-19e2a75a28cc",
  "messageId": "1d2b7c50-c1ac-11f1-bdf6-19e2a75a28cc",
  "subject": "Hello team",
  "from": [{"name": "Alice", "email": "alice@external.com"}],
  "to": [{"name": null, "email": "marketing@linagora.com"}],
  "cc": [{"name": "Bob", "email": "bob@linagora.com"}],
  "bcc": null,
  "date": "2026-10-06T10:00:00Z",
  "timestamp": "2026-10-06T12:00:00Z"
}
----

`subject`, `from`, `to`, `cc`, `bcc` and `date` are `null` when the message lacks the matching header. `mailboxPath`
changes when the mailbox is renamed, `mailboxId` does not. `date` is the `Date` header, `timestamp` is when the event
was produced.
